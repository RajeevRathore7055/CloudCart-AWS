Section 1

Cloud Architecture

User / Browser CloudFront (optional CDN) Load Balancer (optional) EC2: Nginx + FastAPI RDS MySQL
Supporting services: S3 images IAM role VPC + Security Groups CloudWatch
Request path: the browser calls CloudFront or the load balancer, which forwards to the EC2 server. FastAPI reads or writes MySQL on RDS and links to images in S3.
Stateless design: sessions live in a signed cookie, data in RDS, images in S3. Any new EC2 copy can serve any user. That is what makes scaling possible.
Be honest in the viva: CloudFront, load balancer and auto scaling are optional extensions. The cards below show which parts are really verified.

Section 4

Cloud Service Models

IaaS: Infrastructure

Amazon EC2 gives a virtual server. We install the OS packages, Nginx, Python and the app ourselves. AWS manages the physical hardware; we manage everything above the virtual machine.

PaaS: Platform

A PaaS (Google App Engine, AWS Elastic Beanstalk) runs your code without you managing servers. CloudCart does not use a full PaaS. Amazon RDS is a managed service in the same spirit: AWS patches and backs up the database engine for us.

SaaS: Software

CloudCart itself is delivered to shoppers as SaaS: they use it in a browser, with nothing to install. Note the difference: AWS sells us IaaS and managed services; we provide SaaS on top.

Section 5

Virtualization

Physical server Hypervisor Virtual machine EC2 instance CloudCart app

One physical machine is split into many isolated virtual machines. Each gets its own virtual CPU, memory and I/O. That sharing is why a student can rent a t3.micro for a few hours, and why AWS can start (provision) it in about a minute. When we stop the instance the resources return to the pool.

Section 7

Disaster Recovery

Database backup

RDS automated backups (set to 7 days) plus manual snapshots allow restoring the database to a new instance.

Recovery

Restore the snapshot, then point DATABASE_HOST in .env to the restored instance.

Redeployment

The code lives in GitHub. A new EC2 instance is rebuilt by git clone and deploy/ec2_setup.sh.

Data availability

Product images in S3 survive loss of the server. Multi-AZ would add database failover (extra cost, not used).

Recovery status:  not tested. This page describes the procedure; do a restore test before claiming it works.
